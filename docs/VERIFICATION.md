## Test device

- Retail Android 16.0 phone, API 36
- arm64-v8a, 4 KiB memory pages
- No root
- A physical macOS laptop as the hotspot client for the sharing tests
- A temporary upstream test server; credentials were never written to the repository, APK or logs

## Core and routing

`scripts/core_smoke.py` runs the pinned macOS host core against configs generated by the app and local fixtures. It verifies:

- SOCKS5 username/password authentication and domain routing through an upstream.
- UDP ASSOCIATE echo through an authenticated upstream.
- Wrong upstream password is rejected while direct requests still succeed.
- The local shared proxy accepts the correct password and rejects a wrong one.
- Converted subscription `PROXY` rules use the authenticated upstream; `REJECT` blocks; `DIRECT` bypasses a deliberately broken upstream password.
- HTTP CONNECT and SOCKS5 both reach an HTTPS origin.

## Subscription test

A real `sr_cnip.conf` list was downloaded on the phone:

- 392 rules total
- 371 `DOMAIN-SUFFIX`, 17 `IP-CIDR`, 2 `DOMAIN-KEYWORD`, 1 `GEOIP`, 1 `FINAL`
- Original order preserved
- `GEOIP,CN,DIRECT` produced a downloaded China geo-IP rule set
- `FINAL,proxy` selected the final route
- `sing-box check` accepted the generated config
- A deliberately invalid refresh did not overwrite the previous cache timestamp
- Only `[Rule]` entries were imported; General, URL Rewrite and MITM sections were ignored
- Unsupported rules, policy groups and options produced an error and kept the old cache

## Build and packaging checks

- JVM unit tests: 11 tests, 0 failures/errors (the count will grow as tests are added).
- Android lint: 0 errors; warnings are reviewed in CI output.
- Each ABI APK contains the matching `libsingbox.so` and `libhev-socks5-tunnel.so`.
- The universal APK contains all four ABIs.
- The manifest exposes `en`, `zh-CN`, `ja`, `ko` and `ru` locales.
- `apksigner verify` reports a valid signature.
- `aapt dump badging` reports the expected version, `minSdk 26` and `targetSdk 35`.
- The runtime config is private and deleted on stop; no credentials are included in the APK or repository.

## Not verified

These are known gaps, not claims of support:

- Android 16.1 app-defined hotspot name/password and band APIs.
- armeabi-v7a, x86 and x86_64 on real hardware (only build/package inspection).
- 16 KiB page-size devices and kernel configurations that reject the bundled executables.
- Third-party VPN apps running at the same time (Android allows only one VPN).
- Long-term background survival under aggressive OEM battery managers.
- Large numbers of simultaneous hotspot clients.
- Subscription servers that require client certificates, custom headers or non-HTTPS transport.
- UDP behaviour for every upstream provider; SOCKS5 UDP requires upstream UDP ASSOCIATE support.

If you can test one of these, please open an issue with the device model, Android version, ABI, app version and the relevant log excerpt (with credentials removed).
